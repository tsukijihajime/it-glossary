# IT用語辞書

新入社員や非技術者の方が、IT用語をやさしい言葉で調べられる静的サイトです。GitHub Pages で公開し、Teams のチャネルからも参照できます。ビルド作業は不要で、HTML / CSS / JavaScript とデータファイル（JSON）だけで動きます。

## 概要

- 対象: 新入社員・非技術者
- 主な機能
  - 用語の検索（用語名・読み・解説文）
  - 分野（カテゴリ）とレベル（1〜3）での絞り込み
  - お気に入り登録
  - 関連用語へのリンク
  - 「データの入出力」パネルから、JSON / CSV のエクスポート・インポート

## 重要な注意（掲載ルール）

このサイトは公開リポジトリと GitHub Pages で公開するため、**URL を知っていれば誰でも閲覧できます**。

- 掲載してよいのは、一般的な IT 用語だけです。
- 社内固有の略語、顧客名、案件名、社内システム名は**掲載しないでください**。

## GitHub Pages の公開手順

1. GitHub で新しいリポジトリを作成します（Public）。
2. ローカルのリポジトリを push します。
   ```
   git remote add origin git@github.com:<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
3. GitHub のリポジトリページで **Settings** を開き、左メニューの **Pages** を選びます。
4. **Build and deployment** の Source で **Deploy from a branch** を選びます。
5. Branch で **main** / **(root)** を選んで Save します。
6. 数分待つと、ページ上部に公開 URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）が表示されます。URL を開いて表示を確認してください。

## Teams から参照する手順

1. 対象のチャネルを開き、タブ右端の「＋」を押します。
2. 一覧から「Web サイト」を選びます。
3. タブ名を入力し、GitHub Pages の URL を貼り付けて保存します。

## 用語の追加・更新方法

### 方法 A: data/terms.json を直接編集する

`data/terms.json` を編集してコミットします。1 用語は次の項目を持つオブジェクトです。

| 項目 | 内容 |
| --- | --- |
| id | 用語の識別子。半角英数字とハイフン（例: `ip-address`）。重複不可 |
| term | 用語名 |
| reading | 読み（ひらがな） |
| fullName | 正式名称・英語表記（なければ空でも可） |
| category | 分野。次の 8 種から 1 つ |
| summary | 一行の要約 |
| description | 解説文（2〜4 文） |
| analogy | 例え話 |
| example | 使用例（実際の会話での使われ方） |
| related | 関連用語の id の配列（例: `["dns", "router"]`） |
| level | 難易度。1〜3 の数値（1 が最も易しい） |

category に使える値:

- ネットワーク
- セキュリティ
- クラウド
- 開発・プログラミング
- データ・AI
- ハードウェア・組込み
- プロジェクト・業務
- よく聞く略語

編集後は `node --test` を実行してデータの整合性を確認してから、コミットします。

### 方法 B: サイトのインポート機能で確認してから反映する

1. サイトの「データの入出力」パネルから、JSON または CSV をインポートします。
2. 画面上で表示や検索、関連リンクの動作を確認します。
3. 問題なければ「全件 JSON」をエクスポートします。
4. ダウンロードしたファイルで `data/terms.json` を置き換えます。
5. `node --test` を実行して整合性を確認します。
6. コミットして push します。

CSV を Excel で編集する場合の注意:

- **UTF-8 BOM 付き CSV** で保存してください（Excel の「CSV UTF-8（コンマ区切り）」）。そうしないと文字化けします。
- `related` 列は、用語の id を `|` で区切って入力します（例: `dns|router|dhcp`）。

### インポートの反映範囲

サイト上のインポートで追加した用語は、**その人のブラウザの中（localStorage）にだけ**保存されます。他の人には表示されず、サイトの公開データも変わりません。全員に反映するには、方法 A または B で `data/terms.json` を更新して push します。不要になったローカル追加分は「ローカル追加分をすべて削除」で消せます。

## 開発者向け

### ファイル構成

```
index.html        画面
style.css         スタイル
app.js            画面の動作
lib.js            検索・CSV/JSON 変換などのロジック
data/terms.json   用語データ
tests/            テスト（lib.test.js, data.test.js）
.nojekyll         GitHub Pages で Jekyll 処理を無効にする
```

### ローカルでの確認

データを fetch で読み込むため、`index.html` を直接開く（file://）と動きません。簡易サーバーを使います。

```
npx --yes http-server -p 8080 -c-1
```

ブラウザで `http://localhost:8080/` を開きます。

### テスト

```
node --test
```

引数は付けずに実行してください（Node 24 では `node --test tests/` が失敗します）。

## 解説文の書き方ルール

- 文体は「です・ます調」にします。
- 非技術者が読んでわかる言葉で書きます。専門用語を使うときは、その場で言い換えるか、関連用語にリンクします。
- `description` は 2〜4 文にまとめます。
- `analogy` に身近なものへの例え話を、`example` に実際の会話での使用例を書きます。
- 社内固有の情報（顧客名・案件名・社内システム名など）は書きません。
